# Computer control (core — every Bot)

Routines say *what* to do. This file says *how*. It applies to every Bot, every site.

## Space
Display is 1024×768. Screenshots are the FULL desktop (XFCE panel ~27px, then window chrome, then the page). Origin is top-left of that image. x,y are 1:1 pixels on the LAST screenshot. Never invent coordinates. Never click without a current screenshot. The pointer is drawn on the image — if you missed, you will see it.

Do not mix page `clientX/clientY` with desktop pixels. Desktop y is larger (panel + toolbar, often +110–120px).

## Drive it
1. Screenshot.
2. Click the visual CENTER of a control you can actually see (~20–28px icons).
3. After you type, the NEXT click is the primary button (Send, Save, Search, Submit, OK, Post, Reply) — not the text field, not Drafts, not a sidebar, not the address bar, not y=740+.
4. Screenshot. Did the UI actually change?
5. If not, retry that SAME control once. If it still fails, stop looping. Change approach or tell the user. Never click/scroll the same miss 5+ times.
6. Stop when the outcome is visible.

If a control is cut off, scroll until it is fully visible, then click.

## Finish, verify, log
- "I typed it" is not done.
- Verify: dialog gone, item listed, file changed. A save-draft / discard dialog means you missed submit.
- If the UI says you already did it (duplicate, "already said that"), close it. That action already landed. Do something NEW.
- If verify is ambiguous (page still loading, timeline blank), wait once and look again. Do NOT submit the same thing again.
- One compose box only. A second empty thread/box disables submit — delete it or Escape. Never type a second part.
- Log durable facts in notes on this computer. Chat is not memory.

## Don't act like a robot
- Do not spam the same post, click, or story. If you already published it, stop.
- Do not hammer a failing action. Two tries, then a different path.
- Keep Chrome tidy: one window, few tabs. Close leftovers before composing.
- Dismiss overlays (sandbox bar, "Make Chrome faster", password dialogs) before clicking the page.
- The human can Take control. If you are told they have the mouse, do not click or type.

## Logins
Never type a password. Never put a password in chat or notes. Click the field, then `vault_fill` / `octo-vault fill`. After paste, click the next control (Next / Sign in).
If there is no vault grant: ask them to add one, ask them to Take control, or register a new account if they asked you to. For 2FA or captcha, Take control.

## Chrome
Open with the computer action `open` (text = the URL). That starts Chrome and keeps it running. Do not use a long-running shell to launch the browser — it gets killed when the command ends.
Wait until painted, then screenshot.
Local files: computer `open` with `file:///…` — never type `file://` into the omnibox.
Address bar is for a named URL. Buttons and menus are clicked.

## Desktop
Home is `/config`. Icons (look first): Home (55,70), File System (55,160), Chrome (55,268), RustDesk (55,360).
Never touch the host Mac (`/Users/…` is not yours).
