## Bugs found / fixed
- **Take-control asks on cloud never notified**: prompt told the model to write "press Take control" as text; and for Claude-CLI turns the tool runs on the desk (mcp-sub8), so the Worker-side hook never fired. Attention is now recorded from the relay's tool event.
- **One-job policy vs reminders**: reminders (`once` triggers) are excluded from merge/overlap/solo logic; a new cadence replaces a merged row's stale triggers. Tool text/rejection message point "remind me…" at `once_at`.
- **Mid-turn subprocess writes were clobbered** by runUserTurn's emit callback (`upsertBot(bot)` per message event) — now a field-level patchBot. Root cause of every "created but not on the record" routine/reminder this evening.
- **One-off reminders** did not exist (and the model fabricated "Set"): added `once` triggers (`once_at`), classifier bypass when a trigger is explicit, auto-disable after firing.
- **Claude Code built-in tools leaking on desks**: RemoteTrigger/Cron*/ScheduleWakeup/Monitor/PushNotification now disallowed alongside SendMessage/ListAgents, for local AND cloud desk turns (`DESK_DISALLOWED_TOOLS`).
- **Memory writes landed outside the digest's directory** (`<root>/profile.md` vs advertised `<root>/memory/profile.md`) — relative memory paths now resolve inside `memory/`.
- **Removed teammates leaked their X display + Chrome** in the shared container (pids/memory never returned). `vm.stopDisplay(container, n)` now runs on all three delete paths (DELETE /api/bots/:id, remove_teammate in mcp-sub8 and agent).
- **Cloud closing narration after send_message** ("Sent … to the user.") no longer posts as a second bubble (relay reply carries a `spoke` flag).
- **Guardrail:** cloud `npm run deploy` now type-checks first.
- **Cloud lead lost its handoff context** (fresh CLI turn + no delegation lines in its thread) and **coalescing only merged queued turns** — fixed: handoff rows in the chief thread, run-time report brief, 8s coalescing grace (cloud b181966 / 9bd6896 / 4f1af1a). Cloud group tasks now match local: one combined answer.
- **Lead never followed up after a single handoff** (flush skipped the report turn without a tracked job) — the lead now always hears a completed handoff set in one coalesced turn; silence is its call via nothing_to_add. Lead's closing "Sent." after a send_message no longer posts as a second bubble.
- **Routine upserts from the desk subprocess** now mutate under the bots.json lock (patchBot) instead of getBot→upsertBot (a lost-update pattern). 4 more getBot→upsertBot sites remain in mcp-sub8 (memory persist, await_shell, ...) — same fix wanted.
- **Cloud workers' results never reached the chief** — report block used `reply.content`, empty for CLI turns that answer via send_message. Now falls back to the worker's last visible message of the turn (parity with local deliverWorkerAnswer). Cloud 4631c4c.
- **Cloud desks ran Haiku** — host harness bundle predates the Sonnet pin. Fixed live with new `cloud/scripts/push-harness.mjs --ip <desk>` (rsync bundle + restart); golden image rebuild kicked off so new desks get it.
